# WorkBuddy for Obsidian 0.10.1

本版本是一次**面向 Obsidian 社区目录审核的合规修复**：把审核报告里列出的问题逐条清零，并补上发布资产的构建来源证明。功能行为不变。

## 本次更新

### 发布合规（审核报告的「发布」区块）

- **移除 Release 里的多余文件**：发布流程原来会额外打包一个 `workbuddy-for-obsidian-x.y.z.zip` 并上传。Obsidian 只认 `main.js` / `manifest.json` / `styles.css` 三个资产，多余文件会让资产校验不通过。打包步骤已从工作流中删除。
- **补上 GitHub 构建来源证明**：Release 现在会为 `main.js` 与 `styles.css` 签发 artifact attestation，任何用户都可以加密验证这两个文件确实由本仓库的源码构建得出。

### 代码规范（审核报告的「源代码」区块）

- **修复唯一一条硬错误** `no-static-styles-assignment`：不再直接赋值 `element.style.*`。
  - 模型下拉框的实测宽度改由 CSS 自定义属性 `--wb-model-select-width` 传递（`setCssProps`），
    `styles.css` 里用 `width: var(--wb-model-select-width, auto)` 消费。
  - 离屏测宽探针的排版样式移入 CSS 类 `.workbuddy-measure-probe`。
- **正则不再含控制字符**：文件名清洗从 `/[\\/:*?"<>|#\[\]^\x00-\x1f]/g` 改为按码位逐字符判断，
  同时消除了「意外的控制字符」与「不必要的转义字符」两条告警。该实现现由 `src/core/local-upload.ts`
  统一导出，`chat-view.ts` 里重复的一份已删除。
- **去掉多余的类型断言**：`workbuddy-client.ts` 的 `_meta`、`chat-view.ts` 的 `containerEl` 与
  `replaceRange` 的 `to` 参数都不需要断言。
- **修掉 Promise 误用**：5 处 `addEventListener(..., async () => {})` 改为 `() => void fn()`，
  不再把 Promise 丢给期望 `void` 的回调。
- **弹出窗口兼容**：`requestAnimationFrame` → `window.requestAnimationFrame`；
  `instanceof Element` → `instanceOf(Element)`（跨窗口安全）。
- **改用 Obsidian DOM 辅助函数**：`document.createDocumentFragment()` → `createFragment()`，
  `document.createElement("a")` → `createEl("a")`，`document.createElement("span")` → `createSpan()`。
- **移除 `require("electron")`**：改为读取 Electron 注入在 `window` 上的 `require`，行为一致。
- **不再用 `String(unknown)`**：`workbuddy-client.ts` 的工具名与 `event-normalizer.ts` 的兜底
  字符串化都改为显式收敛，避免产出无信息量的 `[object Object]`。

### 设置面板改为声明式 API

- 迁移到 Obsidian 1.13.0 起的 `getSettingDefinitions()`：**所有设置项现在都能被 Obsidian 的
  设置搜索搜到**，`display()` 与已弃用的 `setWarning()` 一并移除。
- 「检测 CLI 路径」由原来紧贴输入框的按钮改为独立一行操作项；「自定义快捷指令」通过 `render`
  逃生舱保留原有的多行编辑布局（增删后会调用 `update()` 重建）。
- 数值型设置（字号、上下文字符上限）在写回前收敛回 `number`，不会在 `data.json` 里存成字符串。

### 需要留意的变更

- **最低 Obsidian 版本从 1.7.2 提升到 1.13.0**。声明式设置 API 与 `ButtonComponent.setDestructive`
  都要求 1.13.0+；当前这台机器的 Obsidian 已是 1.13.x，桌面端默认自动更新，正常无需手动处理。
- 旧版 `styles.css` 中的 `ui-monospace` / `system-ui` 兜底已换成普通等宽/无衬线字体栈
  （审核 CSS LINT 报告 Obsidian 1.6.5 不支持 `extended-system-fonts`）。前者仅为兜底项，
  插件启动后始终会写入 `--wb-body-font`，实际观感不变。

## 安装

在 Obsidian「设置 → 第三方插件 → 浏览」中搜索 **WorkBuddy AI** 安装并启用。

手动安装：下载 Release 中的 `main.js`、`manifest.json`、`styles.css`，放进
`<你的知识库>/.obsidian/plugins/workbuddy-ai/`，重启后在第三方插件里启用。已安装旧版本的用户覆盖这三个文件即可，`data.json` 无需改动。

> 注意：插件目录名是插件 ID `workbuddy-ai`（不是仓库名）。从 0.10.0 或更早版本升级时若目录名不同，
> 请以 Obsidian 实际创建/识别的目录为准。

## 前置条件

需要 Obsidian 桌面版 **1.13.0+**，以及已经安装并登录的 WorkBuddy CLI：

```bash
npm install -g @tencent-ai/codebuddy-code
codebuddy
```
